# 🍄 蘑菇团子电子宠物 v2.8（干净版）

纯前端、可离线安装的电子宠物小应用：会饿、会撒娇、会打盹，还能陪你玩六个触屏小游戏。
无后端、无第三方依赖，双击 `启动游戏.bat` 即可在浏览器里玩。

本目录是 **v2.8 的干净版**：只保留运行必需的文件，历史原图、旧模块、旧文档、旧启动器副本、调试页都没有带进来。整包约 **0.62 MB**（上一版 8.4 MB）。

## 二、v2.8 更新

### 2.1 界面信息架构（P0）

1. **状态条合并**：饱食 / 心情 / 等级三格挪到宠物正下方，带数值和进度条，不再分处顶栏与底部。
2. **主按钮 4 格**：`喂食｜游戏｜背包｜更多`。喂食一键弹食物环；背包里没食物时提示后自动跳到食物页。
3. **数量内嵌按钮**：喂食显示可喂食物数、背包显示物品总数（超 99 显示 99+）；签到显示「待签/已签」；宝箱数量放在背包内的开宝箱按钮上。不再用红色圆点角标。
4. **签到收进「更多」**：主界面不再占一格，按钮文字直接标「待签 / 已签」，签完即时更新。
5. **宠物放大**：`62vw / 260px` → `min(68vw, 42vh) / 320px`。
6. **入口收口**：舞台右侧悬浮背包按钮隐藏（代码保留），背包统一从底栏进。

### 2.2 环形菜单圆心修正（本版重点）

旧实现的问题：菜单盒是 `260×260` 的固定盒子，子项却从盒子左上角 `(0,0)` 开始按 `translate` 展开，而定位代码又按「盒子中心」减半宽 —— **圆心实际落在盒子左上角，和计算出的中心差 130px**，窄屏钳制后还会再漂。

现在的做法：

- `.radial-menu` 改为 **0 尺寸锚点**，`left / top` 直接就是圆心本身；
- 子项 `.radial-item-wrap` 放在 `left:50%; top:50%`，并设为按钮同尺寸、用负 margin 回半个宽高，按钮不再自己算偏移；这样角标能贴住按钮右上角、文字标签落在按钮正下方；
- `positionRadialMenu()` 以**团子图片可视区域中心**为目标圆心，向上抬 10px；
- 圆心再按「最大展开半径 + 按钮半径 + 8px 边距」钳制进视口；屏幕窄到放不下整圈时退化为屏幕中心，保证整圈不飞出屏幕；窗口旋转/缩放时若菜单还开着会重新定位。

效果：无论手机还是桌面、图片加载快慢、菜单是 3 项还是 6 项，圆心都稳定落在团子中心。

### 2.3 签到升级为 7 天面板（P1）

「更多 → 签到」现在打开面板：连续签到天数、1–7 天奖励预览（第 1 天谷物×3、第 3 天饼干×2+牛奶×1、第 7 天蛋糕×2+铃铛×1，其余经验+10）、今天是否已签、下一步高亮。签完即时刷新按钮上的「已签」状态。

### 2.4 瘦身

- 移除 8 张 1536px 原始 PNG（约 7.5 MB）。WebP 已是唯一图源，加载失败走 CSS 的 🍄 emoji 兜底，不再回退到不存在的 `.png`。
- 不带入 `js/game-merge.js`（合成工坊已下线且无引用）、`README_V2.6_备份.md`、`启动游戏_旧副本V2.6.bat`、`tests/debug/`、`tests/bat-branches/`。

### 2.5 逻辑修复（build 20261110.4）

- **存档脏数据兜底**：导入/损坏存档里的字符串、`NaN`、负数、越界值统一纠正；等级至少 1、`expNeed` 至少 1、饱食/心情钳制 0–100、道具数量取非负整数、宝箱队列只留字符串、冷却与计数类字段全部转数字，并把旧存档统一标成 `dataVersion 2`。
- **升级死循环**：`addExp()` 遇到 `expNeed = 0` 或异常值时重置为 100，升级后的 `expNeed` 至少为 1；`renderMain()` 计算经验条也做了除零保护。
- **宝箱不生成**：系统时间被回拨导致 `now - lastBoxGenTime` 为负时先把基准拉到当前时间，避免永远补不出箱子。
- **签到月奖锁死**：断签后开启新一轮连签时重置 `signMonthGet`，第 28 天的月度奖励可以重新获得。
- **离线反向加血**：`offlineFloor` 只约束扣减，原本低于 20 的饱食/心情不会被「保底」拉高。
- **状态图优先级**：饿肚子优先于高兴，`bored` 分支不再不可达；顺序改为 睡 → sad → hungry → bored → shy → play → happy。
- **结算残留**：泡泡游戏结束后清空场上泡泡，避免继续点击加分；翻翻乐时间到若卡在翻回动画，统一复位翻开的牌。
- **版本比较**：`version.json` 的 build 号改为按数字逐段比较，`20261110.10` 不会被判成小于 `20261110.9`。
- **陪玩状态**：打开小游戏时 `isPlaying` 置真、关闭/遮罩关闭时置假并立即重绘，`play.webp` 不再是无用资源。
- 舒心药剂的提示时长改为按 `buffTime` 计算，不再硬编码「30 分钟」。
- **环形菜单可见性**：补回 `.radial-menu.open .radial-item { opacity:1 }`，按钮不再“能点但看不见”；角标只在数量 >0 时显示，返回键不再挂个 0。
- **签到面板状态**：连签未断时，昨天以前的档位显示为已完成，今天高亮在正确档位。
- **存储异常兜底**：隐私模式下读写 `localStorage` 失败不再让启动/音效/引导直接崩；提示容器在最后一条 toast 消失后会自行清理。
- **PWA / Service Worker**：只缓存成功响应，单个预缓存文件 404 不再整轮安装失败；离线缺 js 时不再拿首页 HTML 冒充；清理缓存只删 `mushroom-pet-` 前缀，不误伤同域名其他应用。
- **调试清理**：`清除缓存` 只删本应用的缓存与存储键，不再 `localStorage.clear()` 清空整个域名。
- **存档导入**：补上 `.label-file` 按钮样式（之前 CSS 被删只剩裸 label），并清空 input value，允许重复选择同一个文件。

### 2.6 待机与进食动画（build 20261110.5）

本版先做**零素材动态**，不新增图片，仍使用 `img/` 里的 8 张表情图：

- **待机呼吸**：`#petImg` 加 `idle-breath`，2.8 秒循环的轻微上下浮动与挤压回弹，`transform-origin` 放在脚底附近。
- **随机小动作**：每 9–16 秒随机播一次歪头 / 左右张望 / 小跳；心情低或饿了会降低频率；页面隐藏、弹窗打开或团子在睡觉时不打断。
- **抚摸/升级动作**：原来的一次性 `*-anim` 播放前先暂停待机，播完自动回到呼吸循环。
- **吃东西**：选中食物后，食物 emoji 从团子头顶落到嘴边（Web Animations，680ms），同时团子播放两轮咀嚼挤压，嘴边掉 6 颗碎屑、飘 3 个爱心；约 1.75 秒后重绘表情并回待机。
- **睡觉 Zzz**：`renderMain()` 切到 `sleep.webp` 时给 `#petImgContainer` 加 `sleeping`，右上角 Z 字循环上浮。
- **无障碍**：`prefers-reduced-motion: reduce` 下以上动画全部关闭，只保留静态表情。

动画代码全在 `js/app.js`（`startIdle / stopIdle / playEatAnimation`），状态图仍由 `js/render.js` 统一决定；没有新增依赖，也没有新增图片文件。

### 2.7 旧缓存导致“界面在但按钮没反应”（build 20261110.5）

现象：页面能画出团子、状态条和四个按钮，但点击完全无反应。

根因：浏览器里留着旧 `index.html` / 旧 `app.js` 或旧 Service Worker。v2.8 已删掉 `js/game-merge.js`，旧 `app.js` 仍静态 import 它，模块图 404 → `bootstrap()` 整体不执行 → 静态 HTML 照常显示，但所有 `addEventListener` 都没绑定。同一台机器多个端口（8081/8082/8083/8080）都开过本应用，旧 origin 上还挂着不同 build 的缓存。

修复：

- 12 个 js 模块的静态/动态 import、`index.html` 入口、`tests/smoke.html`、`tests/logic.test.mjs` 全部带 `?v=<build>`；
- `service-worker.js` 的 `CACHE_NAME` 带上 build，`activate` 只清 `mushroom-pet-` 前缀的旧缓存；
- `index.html` 增加启动自检：10 秒内 `window.__petReady` 仍为 false，自动 unregister Service Worker、删除本应用缓存后带时间戳重载一次；`file://` 直接打开时提示改用启动器；
- 两个 `启动游戏.bat` 打开地址改为 `http://127.0.0.1:端口/?v=<build>`，避免旧首页从缓存命中。
- `tests/check_refs.py` 不再硬编码 V2.7 路径，并会剥掉 `?v=` 再校验资源是否存在。

验证：`node tests/logic.test.mjs` 42/42；`python tests/check_refs.py` 资源 4/4、DOM id 43/43、内联脚本 id 全齐；无头 Edge 新 profile 启动 `ready:true`、`build 20261110.5`，浏览器内点喂食可完成“食物飞入 → 咀嚼 → 回待机”。

### 2.9 泡泡猫改成炮台发射 + 六个游戏统一玩法说明（build 20261110.7）

**1）泡泡闯关重做（`js/game-bubblecat.js` + Canvas）**

- 底部一台大炮，拖动屏幕瞄准、松手发射；炮口会反弹左右墙，碰到顶部或其它泡泡后吸附到最近的空格。
- 3 个及以上同色泡泡相邻成组即消除；失去顶部支撑的整片泡泡会一起掉落，掉落数量也算分。
- 每颗发射的泡泡颜色从当前关卡的调色盘随机；右侧显示“下一颗”，方便提前规划。
- 每关目标、限时、颜色数量、每几发落一排新泡泡都会随关卡变化；关卡上限仍是 **999**，进度存 `bubbleLevel`。
- 15 发实测：第 1 发即消除得 30 分，连续发射能一路推进到第 5 关，`bestBubbleCat` 同步刷新。

**2）每个游戏首次进入自动弹玩法说明**

- 六个游戏（接食物 / 戳泡泡 / 打地鼠 / 翻翻乐 / 贪吃蛇 / 泡泡闯关）都有一份图文步骤说明。
- 首次打开某个游戏时自动弹出，玩家可以选择「跳过」或「知道了」；跳过也会记住，不再重复打扰。
- 每个游戏右上角常驻一个「?」按钮，随时可以重新查看该游戏说明。
- 说明内容的唯一维护点是 `js/game-help.js`，首次已读状态存在 `localStorage["mushroomPetHelpSeen"]`，不影响宠物主存档。

验证：首次打开接食物会弹出“接食物怎么玩”，跳过写 `{"feed":1}`；首次开泡泡闯关弹出“泡泡闯关怎么玩”，关闭后进入炮台盘；`bcTarget=51`、画布 `374×583`、开始按钮切换为「闯关中…」。
